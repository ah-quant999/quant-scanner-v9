# quant-scanner-v9

九宝量化 v9 · 只做两件事：**① 判断大盘走势 ② 选出未来收益率最高的股**（v8 精简重建，留精不留多）

## 只有两个页面

| 页面 | 回答的问题 | 卡片 |
|---|---|---|
| 📊 大盘 | 现在大盘什么情况 | 指数快览 · 大盘资金（主力净额）· 平均股价（全市场位置） |
| 🎯 选股 | 买不买 · 买多少 · 买哪几只 | 综合研判 · 今日可买（3 只）· 别碰 · 主线·哪些能进 · 仓位纪律 |

### 🎯 选股页的读法（本站主体）

1. **综合研判**：先给动作（不买 / 买 / 试探）+ 仓位上限 + 加仓条件 x/7，再列大盘定性、所以、怎么做，最后把 5 条理由（攻防档位 / 个股宽度 / 情绪周期 / 危机雷达 / 资金主线）摊在下面。
2. **今日可买**：只给 **3 只**（池上限 5，取因子榜前 3 且不在禁区行业内），逐只带止损 / 目标 / 盈亏比 / 入池理由。研判为「不买」时，这 3 只明确标成**观察名单，不是买入指令**。
3. **别碰**：涨着却净流出（借涨出货）的板块 + 净流出板块 + 缩量新高票。
4. **主线 · 哪些能进**：L1 钱在等进（连续净流入）/ L2 今日接力（涨停最集中，追高区等回调）。
5. **仓位纪律**：单票满档·今日折算 / 首批 / 最多几只 / 止损，加仓检查表，立刻降档条件，回撤纪律。

其余观测类视图（涨停热力、板块资金榜、板块强度榜、龙虎榜、ETF 三合一、概念资金热力、行业树图、运维页…）**一律留在 v8**，不进 v9。

## 与 v8 的关系

- v8 代码冻结不再改；其数据链继续跑。
- v9 只展示、不生产：`.github/workflows/sync_data.yml` 定时从 v8 Pages 拉 4 个 `data/*.js`（约 70KB）后提交，**并在同一次 run 内发布 Pages**。
  （用 GITHUB_TOKEN 提交的 push 不会触发下游 push workflow，拆成两个 workflow 必然 Pages 恒旧。）
- 铁律：数据一律 `window.X` 注入，禁止 `fetch('../data/...')`；任何数据缺失一律明示「未到位」，绝不用陈旧数据冒充当日。
- 陈旧度：每个时间戳按 `dayDiff` 标注，T-1 灰色、≥3 天金色「陈旧 N 天」。
- 降级：`buy.mode=none` ⇒ 个股只作观察；`list_check.met=false` ⇒ 明示榜单闸门未过及原因。
